# 批注 JSON 与执行

安装依赖：`python3 -m pip install pymupdf`（优先使用现有可用环境）。

```sh
python3 scripts/annotate_pdf.py source.pdf notes.json output.pdf --preview-dir previews
```

可添加 `--font /path/to/chinese-font.ttf` 使用本机中文字体；默认内置简体中文字体。输出必须是新文件。坐标单位为 PDF point，使用 PyMuPDF 页面坐标（左上原点），页面号码从 1 开始；旋转页需先根据实际页面坐标核对。数组顺序即全篇编号顺序。编号自动生成，无须填 id。

```json
{
  "notes": [
    {
      "page": 1,
      "rect": [58, 340, 295, 392],
      "badge_rect": [60, 328, 86, 339],
      "label_rect": [60, 60, 285, 80],
      "label": "核心痛点：知识噪声 + 细粒度感知不足",
      "subject": "Problem",
      "detail": "【概念解释】检索文本中的无关信息可能误导模型。\n【现实类比】资料很多，但夹杂错误提示。\n【论文作用】对应后续的知识过滤模块。\n【复习重点】增加资料数量不等于提高信息质量。"
    }
  ]
}
```

上面的坐标只是格式示例，不适用于其他论文。`badge_rect` 必须位于 bbox 上方且靠左或靠右，在原文空白处；`label_rect` 同样要人工确认空白。渲染器检查页面边界、文本遮挡及文字是否容纳得下；它无法判断图片内空白，所以 Figure 页仍需视觉检查。

Popup 的 `title` 为 `Nxx · Zotero Deep Read`，`subject` 为 `Nxx · 类型`，`content` 为 `【Nxx · 类型】` 加详细笔记。编号与短红字写入 PDF 页面，矩形框是真正可点击的 Square annotation。查看器对标题字段显示可能不同，正文始终包含编号。

## 内容选择

方法笔记说明概念、输入输出、为何必要、在全篇中的作用和复习重点。现实类比仅用于帮助理解。

图笔记解释子图、图例、阅读顺序及机制。结果笔记记录指标、数据划分、比较条件和主要数值。消融说明每步改变、数值差异以及和模块动机的关系，不能将逐步叠加的差值解释成无条件独立贡献。

对于作者没有提供的失败边界或参数，明确写“正文未提供”；不要添加无证据的批评、改进模块或额外实验要求。

验证时需检查：全篇编号连续；bbox 与笔记内容对应；无关联箭头；中文显示正常；红字和 badge 不压住原文；图表区域完整但不夹带无关正文；详细 popup 可读取。可选精读索引复用 N 编号。
